DOMAINCORE

Windows Identity & Endpoint Management Platform

Architecture boundaries

Admin workstation → delegated operator group → OU-scoped Active Directory roles → domain DNS/DHCP → managed Windows endpoints. Entra ID and Intune extend identity and device policy after a separately governed tenant integration.

Operational principle

A practical identity lifecycle starts with a validated request, places the object in the right OU, grants role-based groups, records the change, and has a reversible offboarding path.

Status at publication

PowerShell automation: IMPLEMENTED · AD forest/GPO: DESIGNED · Entra ID/Intune: REQUIRES EXTERNAL PLATFORM

What is not claimed

No Windows Server, AD forest, Entra tenant or Intune enrollment is deployed here. PowerShell artifacts are designed for an authorized lab and default to preview/WhatIf for changes.

Implementation notes

  • Exact hostname and project identity are checked by the portal server.
  • HTTP requests redirect to HTTPS; HSTS is host-only with a conservative one-week max-age.
  • Content Security Policy permits only local assets; no third-party analytics or font origin is required.
  • Docker images use a pinned Node base, non-root runtime, read-only filesystem and no published port.
